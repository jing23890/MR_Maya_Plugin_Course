# 4. Maya 场景如何变成可导出的数组

## 4.1 DAG 与 DG

DG（Dependency Graph）描述属性之间的数据依赖。DAG（Directed Acyclic Graph）描述带层级的场景对象关系；Maya 的 DAG 节点也属于依赖图节点，但不是所有 DG 节点都有父子层级。

常见可见对象由 transform 和 shape 配合：transform 管位置/旋转/缩放，shape 承载几何相关信息。材质和许多计算节点则不在这种空间层级里。

```text
|角色组|头发变换|描述Shape       ← DAG 路径
描述Shape.outSplineData         ← 节点属性/Plug
```

`|` 不是文件系统路径分隔符。完整 DAG 路径可区分同名节点；实例化还可能使同一对象拥有不同 DAG 路径，所以“对象身份”和“到对象的路径”不要混为一谈。

## 4.2 从字符串到 API 对象

项目使用的路径：

```python
selection = om.MSelectionList()
selection.add(node_name)
node_object = selection.getDependNode(0)
fn = om.MFnDependencyNode(node_object)
plug = fn.findPlug("outSplineData", False)
data_object = plug.asMObject()
```

| 类型 | 含义 | 应避免的误解 |
| --- | --- | --- |
| MSelectionList | 名称解析/对象条目列表 | 新建一个列表不会自动改变用户选择 |
| MObject | Maya 对象的 API 句柄 | 不是由你 delete 的节点内存 |
| MDagPath | DAG 中到对象的路径 | 实例路径不同，空间变换可能不同 |
| MFnDependencyNode | 对已有依赖节点提供操作的函数集 | 创建函数集不等于创建场景节点 |
| MPlug | 节点属性的访问/连接接口 | 读取输出可能引发求值，不是总能当作无成本字段读取 |

API 1.0 的 `maya.OpenMaya` 和 API 2.0 的 `maya.api.OpenMaya` 不要混用同名包装对象。项目中的 `maya.OpenMayaUI` 是为了取得原生 UI 指针，随后交给 shiboken；这不意味着随意交换两套 OpenMaya 的 MObject。

## 4.3 dirty 与按需求值

输入变化会使相关输出需要重新计算。消费者请求输出时，Maya 按依赖和求值模式更新数据。不能把“节点存在”理解为“所有输出已经提前计算好了”。

这解释了为什么 `read_splines()` 可能耗时：它不仅是在复制字节，还可能触发 XGen 的求值。本工具导出的是当前求值状态，不会替代完整渲染流程执行所有 render-time 操作。

练习 `dg_lab.py` 使用 multiplyDivide 内置节点观察：输入 A=3、倍率 B=2，读 outputX 得 6；修改 A=5，再读得 10。它展示依赖关系，不需要先编写 MPxNode。

## 4.4 对象空间、世界空间和单位

同一个点在 shape 局部空间与场景世界空间的数值不同。C++ 中的矩阵变换经验在这里直接适用，但必须确认接口返回的是哪个空间。

项目保存当前 XGen 样条数组的厘米数值，并不自动把所有 Maya 场景变换烘焙成你猜测的另一种坐标系。跨 UE 时还要考虑轴方向、网格参考姿势、局部坐标、绑定源头模和 UV 约定。

工具界面长度单位与内部数据单位不是可以无条件互换的概念。看到场景显示“米”，不能直接把所有导出浮点数再乘 100。先验证接口和样本。

## 4.5 为什么读取内部二进制

我们没有逐根创建 Maya 曲线再导出，而是读取 XGen 样条数据。本项目先尝试 API 取得原生插件数据；如果 Python 无法访问该 C++ 数据对象的序列化方法，就调用原生内部序列化命令，读临时文件。

这是一个有版本风险的工程取舍：减少场景节点和中间转换，但依赖已实测的内部格式。**不要把逆向确认的布局当成 Autodesk 的长期兼容承诺。** 未知版本被明确拒绝，比悄悄解析出错误头发更好。

## 4.6 解码流程

```text
XGen 序列化字节
  ├─ 16字节头 + JSON 描述
  └─ 分组块
      └─ 前导数据 + zlib 压缩流
          └─ 数值块
              ├─ Positions
              ├─ PrimitiveInfos
              ├─ PatchUVs
              └─ WIDTH_CV
                         ↓
                     SplineData
```

`struct.unpack_from('<I4xQ', ...)` 表示小端 uint32、跳过四字节、uint64；总长 16。这里不依赖 C++ 结构体默认对齐。JSON 中记录的数据引用以高低 32 位分出组号和块号。

`PrimitiveInfos` 的记录为 offset、length、reserved。读取一根曲线时：

```python
curve_positions = p[3 * offset:3 * (offset + length)]
root_uv = uv[2 * offset:2 * offset + 2]
curve_widths = w[offset:offset + length]
```

UV 原数据按顶点存储，但导出只取根顶点的 UV；width 保留每个点的值。跳过短曲线时，必须把位置、宽度和 UV 一起跳过。

## 4.7 把防御性编程放在边界

代码检查块头完整性、长度越界、压缩流结束、引用范围、浮点有限性、顶点记录重叠，以及各数组数量对应关系。

这些检查的作用类似 C++ 读取不可信二进制文件时的边界验证。Python 没有野指针也不意味着“不会出错”：错误长度会造成内存压力、错误索引会读到错误语义、NaN 会污染后续几何计算。

`memoryview` 减少切片复制，`array` 管理连续数值。Python 整数可以超过 64 位，所以解包协议时仍必须显式掩码；不能依靠 C++ 整数溢出的行为去理解 Python。
