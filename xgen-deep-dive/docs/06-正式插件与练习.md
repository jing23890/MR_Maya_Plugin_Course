# 6. 从工具包走向正式插件

## 6.1 可运行的 MPxCommand 示例

`examples/selection_count_plugin.py` 注册命令 `xgLearnSelectionCount`，返回当前活动选择列表的条目数。它不修改场景，不申请节点类型 ID。

在 Maya Python Script Editor 中运行，替换文件路径：

```python
import maya.cmds as cmds
plugin_path = r"D:/Courses/MR_Maya_Plugin_Course/xgen-deep-dive/examples/selection_count_plugin.py"
loaded_name = cmds.loadPlugin(plugin_path)[0]
result = cmds.xgLearnSelectionCount()
count = result[0] if isinstance(result, (list, tuple)) else result
print(count)
cmds.unloadPlugin(loaded_name)
```

源码里的五个关键位置：

| 位置 | 职责 | C++ 对照 |
| --- | --- | --- |
| `maya_useNewAPI()` | 声明本插件使用 API 2.0 | Python API 的约定入口 |
| `SelectionCountCommand(om.MPxCommand)` | Maya 命令类型 | 继承 MPxCommand |
| `creator()` | 给 Maya 创建命令实例 | 静态 creator 工厂 |
| `doIt(args)` | 执行命令、设置返回值 | 虚函数实现 |
| initialize/uninitializePlugin | 注册/注销命令 | 插件加载/卸载生命周期 |

选择列表条目不一定等于唯一节点数量，比如组件选择可能以一个条目表示很多顶点；不要把示例命令误解成“统计所有选择的顶点”。

本机 Maya 2026 测试中，即使 setResult 传入一个整数，cmds 侧收到的也是 `[2]` 这样的单元素列表，因此示例显式取出数值。返回值跨语言绑定的表现应实际检查，不要仅凭 C++ 参数类型推断。卸载时使用 loadPlugin 返回的注册名，而不是假定完整文件路径就是注册名。

## 6.2 Undo 不会自动出现

本示例 `isUndoable()` 返回 False，因为它只读。若正式命令改变场景，需要设计 doIt / redoIt / undoIt 和状态存储，或使用适当的 MDGModifier/MDagModifier 管理可逆操作。

不要只把 isUndoable 改成 True 就认为完成 Undo。导出磁盘文件的副作用也不在 Maya 场景撤销队列的天然保护范围内。

## 6.3 MPxNode 与 MPxCommand 的根本区别

命令表达“一次动作”；节点表达“场景图中的数据关系”。自定义节点的典型结构如下，以下是结构示意，不是可直接加载的完整插件：

```text
initializePlugin:
    registerNode(名称, 合法唯一类型ID, creator, initialize)

initialize:
    创建输入/输出属性
    addAttribute
    attributeAffects(输入, 输出)

compute(被请求的plug, dataBlock):
    只处理自己支持的输出
    从 dataBlock 读输入
    计算
    向输出 handle 写值
    标记输出 clean

uninitializePlugin:
    deregisterNode(类型ID)
```

compute 中不要依赖 UI 选择、随意执行 cmds 创建节点，或者每次打开文件弹窗。它可能因求值需求重复执行；输入、输出、dirty 关系应清楚，线程调度能力也必须如实声明。

正式分发自定义节点需要处理唯一类型 ID 和场景持久化，不能从教程随机抄一个 ID 当成生产 ID。[Autodesk 依赖节点基础](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-SDK/files/Dependency-graph-plug-ins/Maya_SDK_Dependency_graph_plug_ins_DependencyNodeBasics_html.html)

## 6.4 如果你用 C++ 重写本项目

不必从 UI 开始全部重写。可以保留 Python 界面与业务流程，只把测量后确认的热点包装为 C++ 命令/库，或使用公开的 XGen 原生接口研究读取路径。

需要重新处理的事包括：MStatus 错误传播、MObject/MDagPath 生命周期、缓冲区所有权、异常与 Maya API 的边界、插件卸载、SDK 构建和版本兼容。C++ 不会自动解决 Alembic 属性 scope 或坐标约定错误。

一个常见团队结构是：Python 负责用户流程和工具集成，C++ 负责真正需要原生性能或节点求值集成的部分。两者边界仍应像本项目的 SplineData 一样明确。

## 6.5 六个练习，按顺序做

### 练习 A：运行纯 Python 基础

运行 `examples/python_basics.py`。先猜每个断言为什么成立，再看输出。掌握别名、dataclass、闭包、with/finally 和连续数组。

### 练习 B：检查当前选择

先将学习包根目录加入 sys.path（与启动工具时相同），然后导入示例：

```python
from examples import scene_probe, dg_lab
scene_probe.inspect_selection()
# 练习 C 再执行：dg_lab.run()
```

在 Maya 选择一个 transform，执行 `scene_probe.inspect_selection()`。观察 transform 的完整路径、shape 子节点和 API 类型。再不选任何对象运行，应返回空列表而不是异常。

### 练习 C：观察内置节点求值

执行 `dg_lab.run()`，预期返回 `[6.0, 10.0]`。把倍率从 2 改成 4，应得到 `[12.0, 20.0]`。本次创建的节点会在 finally 中删除，原选择恢复；Maya 的 dirty 标记与 Undo 队列仍可能记录这些操作，所以建议在练习场景运行。

### 练习 D：给正式命令加一点功能

加载 selection_count_plugin，选择两个物体，期望返回 2。先保持只读，再尝试用 MGlobal.displayInfo 输出条目路径。修改插件代码后先卸载再加载；不要与同名已注册命令冲突。

### 练习 E：给导出结果增加一个统计项

在 export_grooms 返回字典里加入 `description_count=len(items)`，在 UI 状态文本里显示它。验收标准：原来八个测试仍通过，UI 和无界面 API 都能读取新增字段。这个练习会有意改变代码，因此之后不再满足“与原版 AST 相同”。

### 练习 F：设计 width_scale，不要只改界面

写出你的设计：配置字段 → UI 输入 → 有效范围校验 → 在纯数据层修改宽度副本 → 导出 → 回读验证。

提示：如果直接修改共享的 data.widths，调用者的数据也会改变。要决定并说明函数是否拥有修改输入的权利。测试 1 倍不变、0.5 倍减半、负数被拒绝、源数组不变。这个练习能检验你是否真正理解本项目的数据边界。
