# 5. 界面、异常、测试与发布

## 5.1 Qt 事件循环不是你创建的

Maya 已经拥有 QApplication。项目用 `MQtUtil.mainWindow()` 取得原生指针，再用 shiboken6 包装为 QWidget，作为工具父窗口。

`clicked.connect(self.export)` 把用户事件接到一个函数；layout 负责空间排布；UserRole 保存真实节点路径。UI 类不要再承担解压、格式验证等全部逻辑，否则很难做无界面测试。

Maya 的 Qt/PySide 版本与宿主版本有关。当前项目使用 PySide6，不应把系统 pip 安装的一套 Qt 强行覆盖 Maya 自带库。[Autodesk Qt6 迁移说明](https://help.autodesk.com/cloudhelp/2025/ENU/Maya-DEVHELP/files/Whats-New-Whats-Changed/2025-Whats-New-in-API/Qt6Migration.html)

## 5.2 为什么不能直接把 export 放进 Python Thread

Maya 命令和场景 API 不能普遍假设线程安全，Qt 界面更新也有线程约束。本项目的场景访问和 UI 都留在主线程。`processEvents()` 只在阶段之间让事件得到处理，并未让 XGen 求值变成后台计算。

如果未来需要后台任务，较合理的边界是：主线程读 Maya → 拷贝/冻结为独立数据 → 后台处理纯数据 → 主线程应用结果。第三方 Alembic 绑定是否适合并行使用仍须单独确认。不要从工作线程直接调 cmds 然后希望 GIL 保证 Maya 安全。

`maya.utils.executeInMainThreadWithResult()` 可把调用交回主线程，但依赖 Maya 处理相关事件；主线程等待工作线程、工作线程又等主线程时可能形成死锁。不是把它包在任意函数外就能解决并发。[Autodesk Python 线程说明](https://help.autodesk.com/cloudhelp/2023/ENU/Maya-Scripting/files/GUID-9B5AECBB-B212-4C92-959A-22599760E91A.htm)

## 5.3 取消是协作式的

取消按钮设置状态，业务层的 status() 在阶段边界查询它，抛 ExportCancelled 后走 finally 清理。单次 XGen 求值或 Alembic 写入进行中，没有插入查询就不能立即退出。

不要用强杀线程解决取消：它可能把 Maya、文件对象或第三方库留在不一致状态。本项目只承诺阶段之间取消，不承诺毫秒级响应。

processEvents 允许事件重入，所以 `_busy`、禁用导出按钮和阻止忙时关窗都很重要。它仍不是全面的场景编辑锁，执行期间不应同时修改相关场景。

## 5.4 不保存场景，不等于没动过场景

传统 XGen 转换会临时创建节点。本项目记录节点 UUID、选择集、dirty 标记和 undo 状态，在 finally 中删除转换后新增节点并恢复相关状态。

要诚实理解几个边界：

1. 恢复 dirty 标记不是恢复场景数据。
2. 禁用 undo 记录不等于实现可撤销命令。
3. UUID 集合差要求转换是受控同步过程；无关回调同时创建的节点也可能进入差集。
4. 外部文件、任意插件回调副作用以及进程崩溃，不会被这个 finally 自动回滚。

更严格的生产工具可以隔离转换场景，或精确追踪原生命令返回的节点及所属关系。先明白这里的限制，再决定是否复用这段模式。

## 5.5 如何定位错误

按最近的数据边界判断，而不是只看最后一个 UI 弹窗：

| 现象 | 先检查 |
| --- | --- |
| import 找不到包 | sys.path、包目录层级、模块 __file__ |
| 修改代码没生效 | sys.modules 缓存、旧窗口对象、实际导入路径 |
| 没有找到描述 | 场景节点类型、xgenToolkit 是否加载 |
| XGen 求值形状不对 | Maya Project、贴图/Clumping/缓存路径、当前帧 |
| 数组长度错误 | PrimitiveInfos、偏移、短曲线过滤是否同步 |
| UE 看不到组 | 属性 signedness、scope、数量和导线标记 |
| UE 头发位置不对 | 位置坐标、源头模、单位/轴约定，而非只看 UV |

`traceback.print_exc()` 输出调用栈，用 C++ 调试栈的方式从最底层异常定位。临时诊断建议输出数量、bounds、少量根点和 UV；不要一次把所有发丝数组打印到 Script Editor。

## 5.6 三层测试

**纯 Python 层**：构造合成二进制，测试截断、错误引用、位移、解压限制和短曲线。这类测试快，不需要角色或 UI。

**Maya/Alembic 集成层**：使用 mayapy 和绑定库，写临时 ABC 再回读。必要时初始化 maya.standalone。当前 8 个回归测试主要覆盖解析和写入，不等于完整的 UI 自动化测试。

**真实流程层**：真实场景导出 → Maya/UE 导入 → 数量/几何检查 → 穿戴外观检查。单元测试不能证明发型漂亮，也不能证明全部 Maya 版本兼容。

在本学习目录下：

```powershell
& '<Maya安装目录>/bin/mayapy.exe' -m unittest discover -s XGenGroomExporter/tests -v
& '<Maya安装目录>/bin/mayapy.exe' tests/run_maya_lessons.py
```

第二条启动独立 Maya 运行环境，测试练习和命令插件，不连接正在打开的 Maya，也不打开用户场景。

## 5.7 部署和版本

开发时把包的父目录加到 sys.path；个人安装可放用户 scripts 目录；团队部署还可以使用 Maya module 文件和统一的目录规则。`.mod` 描述的是部署路径，不代表注册了 MPxNode。

普通脚本升级后也可能需要重启 Maya清理旧模块和 Qt 对象。正式插件则涉及 load/unload、命令注销、节点实例和回调清理；有场景实例引用自定义节点时，不能把 DLL 当作普通脚本随时替换。

C++ 插件还受 Maya SDK、编译器、平台和 ABI 约束。Python 工具避免了部分编译问题，但仍依赖 Python 版本、Qt、绑定库和 API 行为；尤其本项目的内部 XGen 布局，不应宣传为跨版本通用。
