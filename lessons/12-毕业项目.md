# 第 12 课：独立交付一个小工具

毕业题目：做一个“导出前场景检查器”。可以复用课程结构，但新增规则和交互要自己设计。

## 需求

用户选择模型，设置面数限制，执行检查；报告包含完整路径、面数、缩放问题和空网格问题；可以过滤显示，并导出带版本号的 JSON。默认只读，不做影响绑定或动画的自动修复。

先写一页设计，回答选择组、选择组件、同名对象、实例、空选择分别怎样处理。再画模块依赖，最后写代码。若需求不清，增加按钮只会让问题更多。

## 分阶段提交

1. 纯逻辑：手工记录能产生正确问题，不依赖 Maya。
2. 场景读取：真实选择变成记录，保留完整路径和明确单位。
3. 界面：参数与结果清晰，失败后没有旧结果冒充新结果。
4. 测试：覆盖正常、空、边界和失败后状态。
5. 交付：新目录启动成功，提供安装与卸载说明。

每阶段都留下一个可运行版本，不要等全部 UI 做完才第一次验证数据。

## 自评表

| 项目 | 合格证据 |
|---|---|
| 需求清楚 | 一页契约，列出范围与失败行为 |
| 分层合理 | core 可在不启动 Maya 时测试 |
| 场景安全 | 默认无修改；新增动作有明确撤销/失败策略 |
| 数据准确 | 不混淆路径、节点身份、单位或面数定义 |
| 生命周期 | 重复打开关闭不积累窗口/回调 |
| 可交付 | 换目录可运行，版本限制与未验证项明确 |

不要用代码行数或界面复杂度评估自己。你能否定位一次错误，并解释为什么这样设计，比记住某个 API 名字更重要。

## 学完后再分方向

- 做工具与管线：继续学批处理、日志、配置、导出数据规范、外部进程与版本管理。
- 做绑定技术：继续学矩阵、坐标空间、DG 节点、变形器和求值。
- 做交互显示：继续学 Qt 生命周期、Viewport 2.0 与绘制接口。
- 需要性能优化：先测量瓶颈，区分 API 调用开销、算法复杂度和 I/O，再决定是否值得学 C++。

这套课程完成的是完整入门开发闭环，不是所有 Maya SDK 专题。能独立交付本毕业题目后，再按你想做的工具继续深入。

官方资料入口见 [参考资料](参考资料.md)。查阅时优先选与你安装版本一致的文档，尤其 Python API 1.0 / 2.0 不要混读。
