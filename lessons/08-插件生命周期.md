# 第 8 课：加载成功不等于生命周期正确

本课不需要编译器。Python 同样可以注册正式 Maya 命令和节点；学习重点是宿主什么时候调用你的代码，以及留下的资源由谁清理。

## import 与 loadPlugin

`import course_scene` 是 Python 模块机制。`cmds.loadPlugin(path)` 则让 Maya 按插件约定调用 initializePlugin，将命令或节点类型注册到宿主中。模块包可以没有插件入口；正式插件需要这些入口。

`maya_useNewAPI()` 是 Python API 2.0 插件的标识约定。别把 `maya.OpenMaya` 的 API 1.0 对象和 `maya.api.OpenMaya` 的 API 2.0 对象当作可任意互换的对象。

注册名、磁盘文件路径、命令名、节点类型名是不同概念。卸载时用 loadPlugin 返回的实际插件名，不要假定完整路径就是注册名。

## 加载与卸载是一对操作

| 建立的资源 | 对应清理 |
|---|---|
| registerCommand | deregisterCommand |
| registerNode | deregisterNode |
| MMessage 系列回调 ID | removeCallback |
| scriptJob ID | kill 对应 job |
| Qt 窗口 | 关闭并释放，断开外部长期引用 |

一个插件注册多个资源时，如果第二步失败，应清理第一步已注册的资源，然后重新抛出错误。不要只写成功路径。课程的两个插件各自只注册一个类型，刻意降低第一遍理解成本。

## 为什么卸载会失败

场景中仍存在自定义节点时，卸载节点插件通常会受阻；撤销队列也可能保留自定义命令实例。正确诊断要检查“谁还在使用它”，而不是习惯性强制卸载。

独立测试进程可以删除测试场景、flushUndo 后卸载，因为它没有用户工作需要保留。工作场景里 flushUndo 会丢弃撤销历史，不能当成普通刷新按钮。

## 一个回调所有者的结构

下面是结构示例，不是自动安装脚本：

```python
import maya.api.OpenMaya as om

class CallbackOwner:
    def __init__(self):
        self.ids = []

    def start(self):
        if not self.ids:
            self.ids.append(om.MEventMessage.addEventCallback(
                "SelectionChanged", self.on_selection))

    def on_selection(self, *args):
        print("选择变化")

    def close(self):
        for callback_id in self.ids:
            om.MMessage.removeCallback(callback_id)
        self.ids.clear()
```

调用者必须保存 owner，并在关闭工具时调用 close。start 的去重避免重复注册；close 的清空避免重复移除。正式产品还需考虑多资源清理中途出错的处理。

练习：在空场景建立 owner、调用 start，改变选择；调用 close 后再改变选择，确认不再输出。不要直接把这个回调粘到生产插件顶层。

验收：你能画出“加载 → 注册 → 使用 → 清理 → 卸载”的过程，并指出每个长期资源的所有者。
