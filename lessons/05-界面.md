# 第 5 课：界面是输入输出层

打开 README 的启动代码，再阅读 [ui.py](../scripts/course_scene/ui.py)。本例使用 Maya 2026 的 PySide6，不需要另装 Qt，也不要替换 Maya 自带的 Python 包。

## 5.1 跟踪一次点击

`scan.clicked.connect(self.scan)` 把信号连接到函数。点击后：清掉旧报告 → bridge 读取场景 → core 应用规则 → 更新文本与按钮状态。

为什么先清旧结果？假设第一次成功、第二次失败，如果旧数据还在而导出按钮仍启用，用户会把旧报告误当新报告。错误处理不只是弹一句异常，还要让界面状态一致。

规则不写在按钮函数里。否则当你需要命令行批处理时，就会被迫创建窗口来复用规则。

## 5.2 谁拥有窗口

`wrapInstance` 把 Maya 主窗口的原生指针包装成 Qt 对象。我们将它作为 parent，让窗口属于宿主 UI；模块 `_window` 保留 Python 引用。两者作用不同，不能只记住“加一个 global 就好了”。

show() 关闭旧窗口并 deleteLater，再创建新窗口，避免重复窗口。deleteLater 由 Qt 事件循环稍后删除；在外部代码里继续保存并调用旧窗口引用是不正确的。

本例没有 scriptJob 和 Maya 回调。真实工具如果注册回调，应保存返回的 ID，在关闭/卸载时移除；否则窗口消失后函数还可能被调用。

## 5.3 主线程边界

按钮函数运行在 Maya 主线程。不要直接开 Python 线程读取/修改 Maya 场景；许多 Maya API 不是线程安全的。计算很重时可先在主线程取得普通数据，再把纯计算交给工作线程，最后通过信号回到主线程更新 UI。

本课程模型检查数据量较小，保持同步。将所有操作包进线程并不能自动解决卡顿，尤其 XGen/场景接口仍可能要求主线程。

## 5.4 用户错误与开发错误

界面显示简短提示，Script Editor 保留 traceback。开发中只 `except: pass` 会把真正原因埋掉。捕获异常是为了恢复可理解的状态，不是为了假装成功。

JSON 保存是磁盘副作用，Ctrl+Z 不会撤销它。课程使用文件选择对话框决定路径，依赖对话框确认已有文件覆盖；需要严格导出事务时看第 11 课。

## 验收

连续调用 show() 三次，只留下一个有效窗口；空选择有提示；阈值为 5 时立方体报告面数问题；保存 JSON 后能读到完整路径。

练习：增加“只显示缩放问题”复选框。它只能过滤显示，不应让底层检查器失去完整问题结果。解释“显示过滤”和“检查规则”为什么应区分。
