# 第 3 课：从一句需求设计工具

需求是：“我想检查选中模型的面数和缩放，并导出报告。”先别做窗口。

## 3.1 写出不含糊的契约

| 问题 | 课程选择 | 为什么 |
|---|---|---|
| 检查范围 | 选中的 mesh 或 transform 的直接 mesh shape | 不突然扫描整个大场景 |
| 面数含义 | polygon 数，不是三角形数 | 两者对四边面不同 |
| 缩放含义 | 父 transform 本地 scale 属性 | 不把它误称为世界缩放 |
| 没选择 | 返回空结果并提示 | 合法状态，不是崩溃 |
| 自动修复 | 不做 | 冻结变换可能影响绑定/动画 |
| 输出 | JSON，带 schema_version | 以后可以升级格式 |

这些限制是产品设计的一部分。一个“修复全部”的按钮不能替代对操作影响的判断。

## 3.2 切成三层

```text
ui.py：控件值、点击、提示
    ↓
bridge.py：从 Maya 读对象 → MeshRecord
    ↓
core.py：记录 → 问题列表；记录/问题 → JSON
```

严格说界面分别调用 bridge 和 core；core 不知道 Maya，也不反向调用 UI。这样你可以用手写数据验证规则，不必启动 Maya。

阅读 [core.py](../scripts/course_scene/core.py)。依次看数据类、inspect、save_report，先跳过 UI。

```python
from course_scene.core import MeshRecord, inspect
records = [MeshRecord("|hero|bodyShape", 8, 6, (1, 2, 1))]
print(inspect(records, face_limit=5))
```

预期两条问题：超过面数阈值、本地缩放不为 1。阈值相等算通过，这是边界条件；对浮点 scale 使用容差，避免把微小误差当成问题。

## 3.3 为什么不直接 print

规则函数返回结构化 Issue，界面才能格式化、测试才能断言、JSON 才能保存稳定字段。只输出一段中文字符串，会让未来按错误类别筛选变得脆弱。

`code` 是稳定标识，`message` 是给人看的解释。不要让程序通过搜索 message 中的“缩放”来判断错误类型。

## 3.4 你来扩展

新增规则 `EMPTY_MESH`：vertices 或 faces 为 0 时报告空网格。先写一个失败测试，再实现规则。不要在这个练习里调用 Maya，直接构造 MeshRecord。

**验收：** 正常网格没有新增问题，空网格有稳定 code，多条记录互不影响。你能指出输入、输出、副作用分别在哪里。

参考答案不会替你完成这个扩展；原始 core.py 保持课程起点，以便你练习。
