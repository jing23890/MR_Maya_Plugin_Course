# 第 1 课：先理解你在扩展什么

目标：跑通第一段代码，并能解释它为什么还不需要 MPxCommand。

## 1.1 四层地图

Maya 自己拥有场景、选择状态、撤销队列和事件循环。你的代码进入这个已有程序工作，而不是像自己写 main() 那样接管一切。

| 形式 | 入口 | 适用情况 | 本课程例子 |
|---|---|---|---|
| 一段脚本 | Script Editor 执行 | 验证想法、一次性操作 | 本课代码 |
| Python 工具包 | import 后调用函数 | 界面、批处理、导出工具 | 场景检查器、XGen 导出器 |
| 命令插件 | loadPlugin 注册命令 | 自定义动作和撤销契约 | courseMoveX |
| 节点插件 | loadPlugin 注册节点类型 | 场景内持续计算的关系 | courseMultiply |

Python 和 C++ 是语言选择；工具、命令、节点是扩展形式。不能把“用 Python 写的”都归为小脚本，也不能因为有窗口就称它为 MPx 插件。

## 1.2 第一次运行

保存正在制作的文件，另开一个空白练习场景。打开 Script Editor，使用 **Python** 标签，执行：

```python
import sys
import maya.cmds as cmds

print(sys.version)
print(cmds.about(version=True))
cube = cmds.polyCube(name="lessonCube")[0]
cmds.setAttr(cube + ".translateX", 3.0)
print(cmds.getAttr(cube + ".translateX"))
```

`cmds.polyCube` 是 Maya 命令的 Python 包装；它的结果是列表，`[0]` 取 transform 名称。不要把请求的 `lessonCube` 当作最终名称：重名时 Maya 会改名。后续必须使用返回值。

这个例子把场景单位下的 translateX 设置为 3，不等于无条件 3 厘米。第 6 课专门设计单位契约。

## 1.3 改写成自己的函数

```python
def create_marker(name, x):
    node = cmds.polyCube(name=name)[0]
    cmds.setAttr(node + ".translateX", x)
    return node

left = create_marker("leftMarker", -2)
right = create_marker("rightMarker", 2)
```

函数隐藏了操作步骤，但场景修改仍然发生在 Maya 中。Python 变量 `left` 是字符串；删除变量不会删除场景对象。

## 1.4 验收

1. 重复执行，观察返回的名字如何改变。
2. 删除 `left` 变量，确认模型仍在；用 `cmds.delete(right)` 删除另一个模型。
3. 用自己的话解释：Python 对象、场景节点、窗口控件为什么不是同一种生命周期。
4. 故意拼错 `.translateX`，在 Script Editor 找到异常最后一行与代码行号。

**通过标准：** 你能不用复制粘贴，写一个接受名字和位置、返回实际节点名的函数。今天不需要创建工具架按钮。
