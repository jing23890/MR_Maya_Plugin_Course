# 第 10 课：在别人的电脑上也能启动

开发时往 sys.path 加路径很方便；交付时需要稳定入口、说明和版本边界。课程包提供 .mod 模板，但不会自动修改你的 Maya 安装。

## 临时加载与持久安装

初学时先按 README 临时启动。确认能运行后，再配置模块：

1. 把课程目录放到固定位置。
2. 编辑 MayaPluginCourse.mod 第一行，将最后的路径改为你的课程根目录。保留开头的 `+ MayaPluginCourse 1.0`。
3. 在 Maya 的 Python Script Editor 运行 `cmds.internalVar(userAppDir=True)` 查看实际用户配置目录。不要猜测 Documents 是否被 OneDrive 重定向。
4. 在该用户配置目录下创建 modules 目录，将 .mod 文件放进去，然后重启 Maya。
5. 执行 `from course_scene import ui; ui.show()`。插件目录被发现不等于插件自动加载，仍需 loadPlugin 或插件管理器启用。

模块根目录下约定的 scripts 和 plug-ins 分别服务 Python 搜索与插件搜索。路径包含空格时按 Maya 模块文件语法正确引用，先验证当前机器，不要复制别人硬编码的盘符。

## 工具架入口

工具架按钮只保留：

```python
from course_scene import ui
ui.show()
```

不要把完整几百行工具复制进按钮，否则你更新文件后按钮仍在跑旧代码。图标、按钮、工具包版本应该可追溯到同一份安装。

## 版本不是看扩展名判断

Python 文件也有兼容性：Python 语法版本、Maya 命令/API、Qt 版本都可能变化。本课程直接使用 PySide6，因此不能不经修改就承诺支持使用 PySide2 的旧环境。需要支持多版本时，要列出目标版本、适配差异、逐版本验证，而不是包一个 try import 就说全部兼容。

本课程不包含 C++ 构建。以后学习原生插件时，还会增加 SDK 与二进制兼容的问题；现在先把 Python 工具交付流程做好。

## 发布内容

应该包含源码、安装说明、最低环境、例子、测试步骤、已知限制。不要包含用户场景、临时缓存、私人路径日志、SDK 库或凭据。公开发布自定义节点前要解决第 7 课的节点类型 ID；准备开源时由你决定许可证，不能把“放到 GitHub”当成自动授予某种许可证。

练习：把课程包解压到另一个目录，仅修改安装路径，重新启动工具。若仍偷偷依赖旧目录，说明交付没有完成。

验收：能清楚区分“模块安装”“加载正式插件”“打开界面”这三个步骤；卸载时知道移除哪个 .mod、哪个按钮和哪个插件。
